# SpeedPulse v1.0.0 — First Stable Release

SpeedPulse is an open-source browser-based connection-speed dashboard with an optional **ASP.NET Core 10** backend. This is the first stable GitHub release.

## Highlights

- Browser speed testing for download and upload throughput, HTTP latency, approximate jitter, and failed HTTP probes
- Charted readings, a connection dashboard, result history, comparisons, CSV export, and sharing tools
- Responsive interface, themes, app installation assets, and scoped PWA caching
- Developer Labs with backend health/config checks, HTTP diagnostics, browser capability reports, clearly labeled simulations, and JSON export
- Self-hosted ASP.NET Core 10 backend, health/config APIs, size-limited test transfers, and per-IP request limiting
- GitHub Pages website: https://sanskarin.github.io/SpeedPulse/

## Important fix included in v1.0.0

The public-site speed test previously showed an intrusive generic alert when the upload phase could not complete even though ping/download had already succeeded.

- Cloudflare upload requests now provide the payload size via the `bytes` query parameter.
- Fixed an undefined `updateLatencyPoint()` call in the live chart that could interrupt the test after successful download/ping readings. The graph now charts observed download/upload readings without inventing latency values.
- A failed upload no longer discards successfully measured ping and download results or displays a browser alert.
- The upload reading is shown as **unavailable** (not zero or a fabricated measurement) when the upload endpoint fails.
- History and CSV export distinguish unavailable readings from real zero measurements.
- JavaScript/service-worker caches refresh on version update, preventing the old bundle from remaining pinned.
- New regression tests cover both the Cloudflare URL and partial-result behavior.

## Downloads

- **SpeedPulse-v1.0.0-web.zip:** the static website. Extract and host with any static server. Uses external Cloudflare test endpoints.
- **SpeedPulse-v1.0.0-linux-x64.zip:** self-contained ASP.NET Core host for Linux x64.
- **SpeedPulse-v1.0.0-windows-x64.zip:** self-contained ASP.NET Core host for Windows x64.
- **SpeedPulse-v1.0.0-osx-arm64.zip:** self-contained ASP.NET Core host for Apple Silicon macOS.

The ASP.NET Core packages contain the same frontend in `main-files/` plus the local test server executable. Extract an archive and run the included `SpeedPulseBackend` program (`SpeedPulseBackend.exe` on Windows), then open the address shown in the terminal. Native executables are not code-signed; operating-system warnings and quarantine policies may apply.

Source archives generated by GitHub are available separately. The releases workflow verifies the web app and builds the backend before publishing.

## Measurement and privacy notes

- GitHub Pages serves **static files only**. It **does not run ASP.NET Core**. Use Cloudflare mode there; use the local option only on a running ASP.NET Core host.
- Results are estimates affected by browser, device, server, and path. The displayed failed-HTTP-probe fraction is **not** true IP packet loss.
- Cloudflare test endpoints may reject uploads, be rate-limited, or experience cross-origin restrictions. SpeedPulse will keep completed measurements and explicitly label any unavailable stage.
- Running a speed test transfers data to the selected endpoint. Browser history and settings stay in local storage. External endpoints can receive network metadata.
- The local test server is intended for trusted environments. Secure it before making its traffic-generating endpoints publicly reachable.
